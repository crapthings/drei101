# 学习页内容规范

本规范用于 04 及后续分组的教学内容优化。保留现有目录名称、顺序、导航和页面结构。

## 优化范围

- 优化章节正文、说明卡片、实验、代码讲解和参数说明，中英文同步。
- 每个导出页面可以独立阅读；相关 API 可用于比较，但不能要求用户跳到另一页完成本页实验。
- 对照项目安装版本的实现、场景代码和实际控件核实事实、单位与默认值。
- 必要时补足关键示例片段；不顺带新增功能、重做演示或扩展为完整的 Three.js 基础课程。
- 演示无法证明某个行为时，调整实验说明；确需修改演示的，单独明确修改原因和范围。

## 章节职责

| 章节 | 必须回答 | 避免 |
| --- | --- | --- |
| 概念初识 | 它是什么，输入什么，得到什么，与近似功能有何区别？ | 开头堆术语，只复述 API 名称 |
| 设计缘由 | 不用它需要自己处理什么，它负责解决哪部分？ | 泛称简化开发或提升效率 |
| 交互演示 | 从什么状态开始，改什么，看哪里，发生什么，为什么？ | 只要求调整参数、观察效果 |
| 应用场景 | 哪个具体业务需求与它的能力匹配？ | 只列行业或场景名称 |
| 使用边界 | 哪些条件不适合，有什么代价，可考虑什么替代方案？ | 每页重复注意性能 |
| 代码解读 | 哪几行决定核心行为，代码如何对应演示？ | 逐行翻译语法，只贴完整代码 |
| 参数解析 | 常用参数如何选择，单位是什么，哪些参数相互影响？ | 只有类型和默认值，穷尽冷门属性 |

## 正文与卡片

正文建立完整的因果关系，卡片解释一个具体问题。两者不要重复，不为凑数量拆卡片。

先给可理解的描述，再引入术语；首次出现的必要术语应就地解释。保持准确，不使用没有条件的性能或兼容性保证。

卡片标题应具体，例如「缩放图片，还是扩大显示框？」。内容说明 scale 改变场景平面尺寸，zoom 改变框内采样范围，再给出选择依据。

实验只使用当前页面已有控件。独立实验注明重置；连续实验写明依赖前一步。区分库默认值、本例初始值和控件范围。

## 每页验收

- 用户能说明它具体完成什么。
- 用户能解释为何选择它，而不是相似功能。
- 用户能预测至少一个关键参数变化后的结果。
- 用户能从最小示例开始使用，并知道素材和运行环境前提。
- 用户能判断何时不适合使用，以及下一步可考虑什么。

核对中英文结构与含义，检查说明与代码、控件一致；有具体视觉预测的实验应在浏览器中观察。记录未验证的条件，不把缺少证据写成已通过。不因此运行项目规则禁止的构建、测试或开发服务命令。
